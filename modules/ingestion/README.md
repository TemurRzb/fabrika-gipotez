# ingestion

Приём и предобработка данных: парсинг xlsx/docx/pdf/png, OCR сканов, нормализация метаданных.

**Выход должен соответствовать** [`schemas/document.schema.json`](../../schemas/document.schema.json).

## Статус скелета

| Формат | Статус |
|---|---|
| `.docx` | работает (`python-docx`) |
| `.pdf` с текстовым слоем | работает (`pdfplumber`) |
| `.xlsx` | заглушка, `NotImplementedError` с TODO |
| `.png`/`.jpg` (сканы, нужен OCR) | заглушка, `NotImplementedError` с TODO |

Функция `ingest(file_path: str) -> dict` в [`ingest.py`](ingest.py) — единственная точка входа модуля.

## MVP на случай нехватки времени

Если времени совсем не хватает — оставить как есть (docx + pdf с текстовым слоем работают, xlsx/OCR кидают понятный `NotImplementedError`). Это уже достаточно для команды: `rag_core` и дальше по пайплайну может работать на docx/pdf-документах и на `mock_data/documents/*.json` для форматов, которые не успели доделать.

## Рекомендованные библиотеки

- `python-docx` — .docx (уже используется)
- `pdfplumber` — .pdf с текстовым слоем (уже используется)
- `openpyxl` — .xlsx
- `pytesseract` + `Pillow` — OCR (требует системного Tesseract) ИЛИ Yandex Vision API

## Как тестировать независимо

```bash
# из корня репозитория
pip install -r requirements.txt
pytest modules/ingestion/tests/test_ingestion.py -v

# ручной прогон на своём файле
python modules/ingestion/ingest.py "путь/к/файлу.docx"
```

Тесты в `tests/test_ingestion.py` сами создают временные .docx/.pdf файлы и валидируют результат `ingest()` через `schemas/validate_schema.py` — реальные файлы из `Задача 1/` не обязательны для прогона тестов, но пригодятся для ручной проверки на реальных данных.
