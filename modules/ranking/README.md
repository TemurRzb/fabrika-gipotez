# ranking

Ранжирование и обоснование гипотез, преимущественно НЕ-LLM методами (эмбеддинг-близость,
rule-based скоринг).

**Вход:** `raw_hypotheses` ([`schemas/raw_hypotheses.schema.json`](../../schemas/raw_hypotheses.schema.json)) + `constraints`.
**Выход должен соответствовать** [`schemas/ranked_hypotheses.schema.json`](../../schemas/ranked_hypotheses.schema.json).

## Статус

Функция `rank(raw_hypotheses: dict, constraints: dict) -> dict` в [`rank.py`](rank.py):

| Score | Метод сейчас | TODO |
|---|---|---|
| `novelty` | **реальные семантические эмбеддинги** — та же модель, что в `rag_core` (`intfloat/multilingual-e5-small`, переиспользуется через `rag_core.retrieve.get_embedding_model()`), + косинусная близость между гипотезами в батче | — |
| `feasibility` | rule-based: доля materials/equipment из constraints, упомянутых в тексте | доработать веса, учитывать бюджет |
| `expected_value` | rule-based: парсинг чисел (%) из `target_property_impact` | при необходимости — учитывать несколько чисел/диапазонов |
| `risk` | rule-based: ключевые слова-маркеры риска (патент, автоклав, капзатраты...) | расширить список маркеров под реальные данные |
| `overall` | взвешенная сумма выше (веса в `WEIGHTS`) | подбор весов вместе с командой на реальных данных |
| `roadmap` | шаблонные 2 шага (лаб -> пилот) | сделать шаги специфичнее под тип гипотезы |

## Как считается novelty теперь

Раньше — хэш-based псевдо-эмбеддинги (детерминированный шум по sha256 текста), не имевшие
отношения к реальному смыслу. Теперь — настоящие эмбеддинги: `rag_core` уже подключил
`sentence-transformers` для RAG, `ranking` просто переиспользует ту же загруженную модель
(`get_embedding_model()` в `modules/rag_core/retrieve.py`) вместо своей.

Задача симметричная (сравниваем гипотезы друг с другом, а не запрос с документом), поэтому
оба текста кодируются с префиксом `"query: "` — так рекомендует сама модель E5 для
симметричных задач (в отличие от `retrieve()`, где документы кодируются с `"passage: "`).

**Проверено на реальном прогоне** (3 гипотезы про золото из упорных сульфидных руд —
двойное цианирование / сульфатизирующий обжиг / автоклавное выщелачивание): novelty вышла
низкой для всех трёх (0.025-0.031). Это осмысленно, а не баг — модель правильно увидела,
что все три гипотезы являются вариациями одной темы ("окислительная предобработка +
цианирование"), просто с разной конкретной техникой. Раньше хэш-шум давал произвольные
несвязанные с содержанием оценки (0.44-0.49 в той же ситуации).

## MVP на случай нехватки времени

Уже не нужен — реальные эмбеддинги подключены. Если модуль `rag_core` вдруг недоступен (не установлен `sentence-transformers`) — `rank()` упадёт при импорте `get_embedding_model`, так что оба модуля теперь связаны этой общей зависимостью.

## Рекомендованные библиотеки

- `numpy` — косинусная близость (уже используется)
- `sentence-transformers` — через `modules.rag_core.retrieve.get_embedding_model()` (общая с `rag_core`, отдельно не устанавливается)

## Как тестировать независимо

```bash
pip install -r requirements.txt
pytest modules/ranking/tests/test_ranking.py -v

python modules/ranking/rank.py
```

Первый запуск в свежем процессе будет медленнее (загрузка модели эмбеддингов) — см. заметки про `HF_HUB_OFFLINE`/`HF_TOKEN` в [`modules/rag_core/README.md`](../rag_core/README.md), если видите ошибки 429 от HuggingFace Hub.
